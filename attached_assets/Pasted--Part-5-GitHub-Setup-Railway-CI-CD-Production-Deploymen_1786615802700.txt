# Part 5: GitHub Setup, Railway CI/CD & Production Deployment
In this final stage, we package the application for production deployment using **GitHub** and **Railway**. This setup ensures that every time your developer pushes code updates to the main branch on GitHub, Railway automatically builds and deploys the new code without downtime.
## 1. Containerization & Production Configuration (Dockerfile)
To run seamlessly on Railway, create a production Dockerfile in the root of your project:
```dockerfile
# Use official lightweight Python image
FROM python:3.11-slim

# Prevent Python from writing .pyc files and buffer outputs
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

# Set working directory inside container
WORKDIR /app

# Install system dependencies (for SSL and PostgreSQL drivers)
RUN apt-get update && apt-get install -y --no-install-recommends \
    build-essential \
    libpq-dev \
    && rm -rf /var/lib/apt/lists/*

# Copy and install requirements first (for caching layers)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy project files
COPY . .

# Run the Telegram Bot entry point
CMD ["python", "main.py"]

```
## 2. Railway Deployment Configuration (Procfile & railway.json)
Railway reads configuration directly from your repository.
### Procfile
```text
worker: python main.py

```
### railway.json
```json
{
  "$schema": "https://railway.app/railway.schema.json",
  "build": {
    "builder": "DOCKERFILE",
    "dockerfilePath": "Dockerfile"
  },
  "deploy": {
    "restartPolicyType": "ON_FAILURE",
    "restartPolicyMaxRetries": 10
  }
}

```

## 4. Deploying on Railway (Step-by-Step)
Follow these steps to deploy the project to Railway:
 1. **Log in to Railway:** Go to railway.app and sign in with GitHub.
 2. **Create New Project:** Click **New Project** → Select **Deploy from GitHub repo**.
 3. **Connect Repository:** Select your endless-telegram-mailer repository.
 4. **Provision Database (PostgreSQL):**
   * Click **+ New** inside your Railway project workspace → Select **Database** → **Add PostgreSQL**.
   * Railway will automatically generate a DATABASE_URL environment variable.
 5. **Configure Environment Variables:**
   Navigate to your app service on Railway → Click **Variables** tab → Add the required production variables:
   | Variable Name | Value / Description |
   |---|---|
   | TELEGRAM_BOT_TOKEN | Token provided by @BotFather |
   | TELEGRAM_ADMIN_IDS | Your Telegram User ID (comma-separated for multiple admins) |
   | DATABASE_URL | Set automatically by Railway PostgreSQL plugin |
   | SMTP_HOST | smtp.yourserver.com |
   | SMTP_PORT | 587 or 465 |
   | SMTP_USER | your_smtp_username |
   | SMTP_PASS | your_smtp_password |
   | ENVIRONMENT | production |
 6. **Persistent Volume (Optional for Asset Storage):**
   * If storing generated email previews or dynamic uploaded brand logos locally, click **+ New** → **Volume** → Mount to /app/assets.
## 5. Production Health & Automatic CI/CD Workflow
Once deployed on Railway:
 * **Automatic Continuous Integration:** Whenever your developer pushes code updates or template additions to GitHub (git push origin main), Railway will automatically trigger a background build, run tests, and redeploy the live bot without interrupting user sessions.
 * **Logs & Monitoring:** Monitor bot activity, SMTP connection logs, and errors in real-time under the **Deployments → View Logs** tab on Railway.
